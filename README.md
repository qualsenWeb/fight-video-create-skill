# Fight Video Create Skill

[![中文](https://img.shields.io/badge/文档-中文-1677ff)](README.md) [![English](https://img.shields.io/badge/docs-English-64748b)](README.en.md) [![Changelog](https://img.shields.io/badge/changelog-更新日志-8b5cf6)](changelog.md)

> 把一句打斗构想，编译成可执行的剧情、动作链、空间路线、分镜和视频生成提示词。

适用于漫剧、真人动作、动画、武侠、仙侠与能力战。参考资料只提供结构、机制和质量标准，不会覆盖你锁定的人物、武器、能力、胜负、时长或结尾。

## 核心能力

| 能力 | 解决的问题 |
| --- | --- |
| **构思到成稿** | 从模糊设定提炼冲突、升级、动作因果、空间调度和镜头结构。 |
| **分层检索** | 按场景、动作/分镜方案、招式库、示例剧本逐层检索，命中后才读取正文。 |
| **招式合理性门禁** | 校验武器形制、距离、姿态、支点、角色能力、时长和动作衔接。 |
| **资料吸收** | 将 `.docx`、`.txt` 等资料按职责拆入场景、导演方案、招式或示例剧本库。 |
| **确定性路由** | 通过关键词、字段权重和语义签名返回可解释的候选，不靠模糊印象套案例。 |
| **可验证交付** | 用路由校验器检查库存、文件、ID、关键词与元数据是否一致。 |

## 快速开始

### 1. 设计一场战斗

将下面的最小输入发送给支持 Skill 的智能体：

```text
调用 fight-video-create-skill：
一个持长枪的男人与一个持长剑的女人战斗。
制作 15 秒、16:9、电影感分镜。
```

Skill 会先提炼锁定事实，再依次处理场景和动作/分镜方案。命中多个方案时，会展示推荐项与其他可选项，并在你确认主方案后继续生成。

### 2. 吸收参考资料

```text
调用 fight-video-create-skill 吸收以下资料：
《竹林打斗.docx》、`河滩战斗.txt`
```

在任何写入前，Skill 会先列出每份资料的：

- 建议入库位置与主要用途；
- 可复用的空间、动作、镜头或剧情机制；
- 与现有资料的重复、冲突和拆分风险。

只有在用户确认后才会去重、写入、更新路由并执行校验。

## 创作工作流

```text
锁定事实
   ↓
场景路由 → 场景摘要或原创场景
   ↓
动作/分镜方案路由 → 用户确认主方案
   ↓
招式路由 → 合理性门禁（按需）
   ↓
示例剧本路由 → 只迁移结构机制
   ↓
剧情 + 动作链 + 空间路线 + 分镜 + 生成约束
```

### 关键原则

1. **用户事实优先**：人物、武器、能力、动作顺序、胜负、时长、比例和结尾不可被案例覆盖。
2. **先路由，后读正文**：自动匹配至少命中一个路由关键词；零命中即按原创处理。
3. **一次一个主方案**：动作/分镜方案必须先确认，未经确认不混合多个方案的默认协议。
4. **招式必须可执行**：每个关键动作都要有起势、轨迹、接触或落空、受力反馈、结果和下一步条件。
5. **案例只迁移机制**：可复用冲突升级、空间阶段、攻防转折、高潮接口和结尾结构，不复制专有角色、连续句子或无关情节。

## 交付内容

未指定格式时，默认输出以下六部分：

1. **采用依据**：确认使用的方案、场景、招式、案例及原创部分；
2. **剧情设计**：目标、冲突、升级、转折、胜负因果和结尾；
3. **角色动作签名**：起手、距离、移动、主战、破招、受击和终结方式；
4. **动作设计**：动作目的 → 身体路径 → 对手响应 → 接触反馈 → 位移结果 → 下一动作条件；
5. **空间路线与分镜表**：人物位置、观察轴、镜头接力、运镜终点和声音；
6. **生成约束**：角色与武器稳定、无身体融合、无回合制复位、无随机越轴、特效不遮挡关键接触。

成稿还必须保证：开场快速进入有效动作；重要动作产生明确结果；上一段末态成为下一段起点；一打多不排队；终结来自前文形成的破绽；最后一帧仍保留主体、摄影机或环境余波运动。

## 资料库

```text
reference/
├── scenes/                                 # 场景、环境与空间路线
├── action-storyboard-design/               # 动作与分镜导演方案
│   └── 招式库/                              # 兵器、武学、身法与连招
└── example-scripts/                         # 示例剧本与成片结构

scripts/
├── route_reference.py                      # 确定性关键词路由器
└── validate_routes.py                      # 路由元数据校验器
```

当前示例剧本库包含 **28 个案例**，覆盖刀剑对决、仙侠远程剑气、水刃清群、建筑多层追击、法阵镇魔、多人协同和宏观能力终结等结构。完整库存与关键词以各目录的 `00-路由元.json` 为准。

## 本地使用与校验

在仓库根目录执行路由检索：

```bash
# 检索动作/分镜方案
python -X utf8 scripts/route_reference.py design --query "竹林 刀剑 追击"

# 检索示例剧本
python -X utf8 scripts/route_reference.py scripts --query "水刃 黑雾 双人清军"
```

资料入库、改名、删除或调整路由后执行：

```bash
python -X utf8 scripts/validate_routes.py
```

Windows 若未注册 `python` 命令，可使用 Python Launcher：

```powershell
py -3 -X utf8 scripts/validate_routes.py
```

路由结果中的 `eligible` 只包含至少命中一个关键词的候选；`available` 仅用于展示可手动选择的完整方案，不代表自动匹配成功。

## 贡献与资料规范

欢迎提交场景、动作导演方案、招式专项和示例剧本。新增、删除、拆分、合并或改名时，请同时：

1. 将内容放入职责最接近的目录；
2. 更新对应目录的 `00-路由元.json`；
3. 使用自然、区分度高的关键词；
4. 运行 `validate_routes.py`，并用强关键词完成路由烟测；
5. 保留来源说明，不把推断内容伪装成原始事实。
